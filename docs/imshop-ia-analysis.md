## 1. IA 병리 맵 — 5개 질문에 스크린샷 근거로 답변

**Q1. 바텀 내비게이션이 존재하는가?**
아니다. 어떤 캡처에도 홈/자산/혜택류의 전역 하단 탭바가 없다. HOME-01에만 카드위젯 하단에 "PAY/쿠폰함/지갑" 짧은 탭 스트립이 있는데 이건 카드위젯 내부 서브탭이지 전역 내비가 아니다. **최상위 이동 수단은 사실상 HOME-04(햄버거 드로어)뿐이다.** 배치2 세션도 독립적으로 같은 결론에 도달함("하단 탭바가 어느 캡처에도 안 보임").

**Q2. 햄버거는 뭘 여는가, 통상 드로어와 뭐가 다른가?**
HOME-04는 6개 탭(지역사랑상품권/SHOP샵/라이프/제로페이/고객센터/설정) + 탭마다 다른 하위메뉴 조합이다. "설정"은 이 6개 중 하나일 뿐이지만, **전역 이동 수단이 이것뿐이라서** 실질적으로 햄버거를 열 때마다 "어디로 가는 메뉴인지"와 "환경설정 메뉴인지"가 한 화면 안에 섞여 있다. 일반적인 드로어(주요 목적지 바로가기)와 설정 허브가 분리 안 된 구조다.

**Q3. 햄버거 하위 화면에서 뒤로가기 누르면 어디로 가는가?**
**스크린샷으로 증명 불가.** 정적 캡처는 인터랙션 전환을 못 담는다. 이건 네 실사용 증언으로만 존재하는 증거다 — 제안요약서에 쓸 때 "관찰됨"이 아니라 "실사용 테스트 중 확인됨"으로 구분해서 표기해야 한다.

**Q4. 알림 안의 설정과 햄버거 안의 설정, 뭐가 다른가?**
NAV-04(알림PUSH설정)가 정확히 이 사례다. 도착지는 하나인데 진입경로가 둘이다: 드로어→설정 경유, 그리고 알림함 화면 자체 톱니바퀴 아이콘 경유. 사용자 입장에서는 "설정을 두 군데서 만난다"가 된다.

**Q5. 화면 간 연결이 뒤죽박죽인가, 구체적으로 어디가?**
PAY-02(충전)와 PAY-03(할인없이충전)이 드로어 하위메뉴에 나란히 별개 항목으로 있다. 정상 충전에서 할인기간이 아니면 에러만 뜨고 "할인없이충전으로 가시겠습니까" 같은 유도가 없다(적어도 캡처된 화면엔 없음). 같은 목적(충전)에 도달하는 두 개의 분리된 문이 있고 서로 연결이 안 된다.

## 2. 확정된 이탈 지점 (우선순위순)

1. **PAY-01 연결계좌 등록** — 은행 20개+증권 20개를 아무 설명 없이 그리드로 던진다. "이게 왜 필요한지"(계좌를 왜 연결해야 충전이 되는지) 설명이 캡처에 없다. 검색 기능도 화면 요소 목록에 없다(확인 필요하지만 없을 가능성 높음). 시니어가 본인이 쓰는 은행을 40개 로고 중에서 찾아야 한다.
2. **PAY-02/PAY-03 갈림길** — "충전"과 "할인없이충전"이 별개 메뉴 항목. 잘못 들어가면 "할인판매 기간이 아닙니다"에서 막히고 대안 경로 안내가 없다.
3. **HOME-01 폴드** — 이미 컨텍스트 문서에서 확정된 부분, 이번에 스크린샷 원문으로 재확인됨.
4. **NAV-04 이중 진입** — 태스크 완료를 막는 정도는 아니지만 "이 앱은 아무 데나 설정이 있다"는 인상을 준다. 신뢰도 문제.

## 3. AI 개입 지점 1차 확정 (컨텍스트 문서 원칙에 이 데이터를 매핑)

컨텍스트 문서 원칙(챗봇 아님=감지형 / 돈 안 만짐=코파일럿 / 온디바이스+정보최소)을 실제 화면에 건다.

- **PAY-01에서**: 그리드에서 일정 시간 이상 스크롤만 하고 못 고르면("같은 화면에 오래 멈춤" 신호) → "어떤 은행을 쓰시는지 말씀해주시면 찾아드릴게요" 같은 개입. 계좌번호 자체를 안 만지므로 정보최소 원칙 그대로 유지.
- **PAY-02 에러 발생 시**: "할인판매 기간이 아닙니다" 뜨는 순간이 감지형 개입의 제일 명확한 트리거다. "지금은 할인 충전이 안 되는 기간이에요. 할인 없이 바로 충전할까요?" → PAY-03으로 코파일럿처럼 짚어준다. 이게 컨텍스트 문서가 원하던 "같은 버튼 반복 취소/에러 발생" 신호의 실제 사례다.
- **NAV-04류 설정 산개 문제**: 화면 구조를 바꾸기보다 AI가 자연어 딥링크 역할("알림 설정 바꾸고 싶어" → 바로 NAV-04로) 하는 쪽이 시간 대비 효율적. 이번 프로토타입 스코프에 넣을지는 시간 보고 결정.

카메라 가맹점 확인 기능은 이번 캡처에 QR가맹점검색(검색창+빈상태)만 있고 카메라 인식 화면 자체는 없음 — 컨텍스트 문서대로 시연 수준으로만 유지하는 게 맞다.

## 4. 디자인 토큰 — 제한적 관찰 (정밀 추출 아님)

이 문서는 전사.md의 텍스트 설명만 봤고 원본 이미지에 직접 접근하지 못했다. 정확한 hex는 스포이드가 필요하고 그건 원본 이미지가 있는 쪽(Claude Code, 캡처 원본)에서 해야 한다. 텍스트로 확인되는 것만:

- 메인 보라(인디고) 계열 — 버튼, 포커스 테두리, 인디케이터 전반에 반복 확인. 이전 상태 점검에서 "iM샵 보라"로 이미 토큰화됐다고 했으니 그대로 이어가면 됨.
- 에러 텍스트 빨간색(PAY-02 팝업 제목)
- 성공 체크 아이콘 보라색 원형(CARD-05)
- 카드 위젯 다크네이비 배경(HOME-01), 카드 자체는 브랜드별로 빨강(대구로페이)/흰색(포항사랑카드) 등 상이
